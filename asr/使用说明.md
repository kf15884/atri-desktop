# Atri 日语识别 0.1.0 — 配套桌面 0.3.0

这是独立的 Windows x64 本地声音识别配套包，不是新版 Koishi 插件。
现有服务器、桌面 0.3.0、token、隧道、Ollama 和 HDS 人格/记忆均不需要重装或改动。
本次只做日语识别，不增加更多画面帧、不加入语音合成或麦克风采集。

## 1. 解压到 D 盘（离线便携，不安装 Python）

将“程序包”和“small 模型包”都解压到同一个目录，例如 D:\Atri-ASR。
两个 ZIP 内的顶层文件夹均为 Atri-Japanese-ASR-0.1.0；合并同名文件夹即可。
不要把模型包再套进 models\models 或多一层 Atri-Japanese-ASR-0.1.0。
最终应能看到：

```
D:\Atri-ASR\Atri-Japanese-ASR-0.1.0\
  start-asr.cmd
  check-files.cmd
  check-service.cmd
  runtime\python.exe
  src\server.py
  models\small\model.bin
  models\small\config.json
  models\small\tokenizer.json
  models\small\vocabulary.txt
```

Python 运行环境、依赖和模型都在该目录；不需要安装系统 Python、pip、CUDA 或另装 FFmpeg。
建议为解压文件和下载包合计预留至少 2GB 空间。这个模型不是 Ollama 模型，不要执行 ollama pull small。
官方 Windows 嵌入式 Python 与依赖已打包；没有修改注册表、系统 PATH、启动项、Windows 服务或防火墙的脚本。
此工具不主动向 C 盘存模型/缓存/音频，但 Windows 自身临时文件、杀毒扫描或崩溃转储不在本程序控制范围内。

## 2. 自检并启动

1. 双击 check-files.cmd：验证交付文件摘要并导入原生依赖。它不启动录音，不证明识别准确率。
2. 双击 start-asr.cmd；等待黑色窗口显示 Ready。不要关闭此窗口。
3. 双击 check-service.cmd；应显示 service=atri-japanese-asr、model=small、language=ja、ready=true、device=cpu。

本服务仅监听 127.0.0.1:8000；不能在另一台电脑访问，也不需要新建 SSH 转发。
ASR 固定 CPU/int8，默认 6 线程，视觉模型继续使用 Ollama；这里不使用 RTX 显存。
关闭服务：在服务窗口按 Ctrl+C。程序未设置开机自启。

## 3. 在现有桌面 0.3.0 中启用声音

先停止观察，再勾选“加入电脑播放声音”，填：

| 项目 | 值 |
| --- | --- |
| 视觉服务 | 保留 http://127.0.0.1:11434/v1 |
| 视觉模型 | 保留 qwen2.5vl:3b |
| 每轮长度 | 首轮先用 15 秒 |
| 本地 ASR 服务 | http://127.0.0.1:8000/v1 |
| 已安装的 ASR 模型 | small |
| 允许向 HDS 同步观察文字 | 首轮不要勾选 |

重要：将旧默认值 SenseVoiceSmall 改成 small；本服务不会把错误模型名静默当成正确模型。
不需要“语言”输入框：服务端已固定 language=ja、task=transcribe，输出日语原文，不自动翻译中文。

选有日语对白的视频播放器，保持窗口可捕获、视频正常播放、系统音量非静音，再开始观察。
首轮完成后，观察记录下方应出现“ASR参考：”和日语文字。辨认不到语音时不补编台词。
画面模型会收到这些日语文字作为不可信参考，结合分镜形成观察；它不是独立的 Atri 人格。

## 4. 验收顺序

1. 本地短对白：画面能读、能见到对应日语原文；字幕可能与口语不同，不要求逐字等同。
2. 静音片段：不应凭空出现连续台词。音乐/歌曲/嘈杂背景仍可能被误识，不承诺全无幻觉。
3. 停止观察：桌面清缓存并停止捕获；重新开始不应混入旧结果。
4. 最后再勾选文字同步；先和 Atri 正常说一句话绑定当前故事，再开始观察并问相关问题。
   /adesk 的“观察资料”应在有效窗口内有缓存；只代表临时缓存，不等于 HDS 必然使用。

本版本沿用桌面 0.3.0 的串行 ASR→视觉识别，总处理受其约 90 秒超时限制。
跟不上时不会无限排队；可能跳过部分片段，所以不是实时字幕、完整听写或完播证明。
音频切片仍按现有观察窗口切分，尚未加入跨轮重叠/VAD边界调度；句子跨轮可能被截断。
ASR 内部 VAD 只过滤片段中的非语音，不等于桌面已经按句子录音。
台词时间戳是提交音频片段内的秒数；桌面现版只显示合并文字，没有升级为播放器时间轴。

## 5. 隐私与声音范围

- Windows 系统声音回环可能包含浏览器、通知等其他应用声音；不是选定窗口独占音频。
- 不使用麦克风。测试前关闭无关发声应用；服务本身不会主动采集任何设备。
- 服务只接受本机主进程 WAV 上传，无网页 CORS、远程 URL、转发、任意文件读写或云端兜底。
- 推理时只加载本地模型；原始 WAV/PCM、转写正文不写服务日志或临时音频文件。
- 本机程序仍可调用此无 token 的回环接口：它不是抵御恶意本机软件的安全边界。
- 停止观察会取消客户端等待并丢弃迟到结果；已进入原生模型的当前计算不能被强制即时中断，可能继续计算到返回，但不会重放进新观察。
- 保留现有桌面约 120 秒原始内存缓存、最近 4 轮报告；不是安全擦除保证。
- 同步关闭时观察留本机；开启后只有现有观察文字发主机，文字可能随 HDS 请求发送给其原有模型供应商。
  现版同步主要是视觉模型结合 ASR 后的观察摘要，不承诺把全部日语原文逐字送入 HDS。

## 6. 常见问题

- 8000 被占用：先运行 check-service.cmd。若就是本服务，无需重复启动；若是其他服务，不要乱杀进程。可手动运行 runtime\python.exe -B src\server.py --model-dir models\small --port 18000，并把桌面 ASR 地址改为 http://127.0.0.1:18000/v1。
- ASR 失败：核对服务 Ready、模型名 small、地址带 /v1；先用 15 秒，暂停其他高 CPU 任务。现版桌面会降级为仅画面，不显示服务全部错误细节。
- 没有“ASR参考”：可能系统声音轨没取得、系统静音、VAD 未检出语音或服务错误；不要仅凭有画面判定声音正常。
- 导入 DLL 失败：先把 check-files.cmd 中的错误发回，隐藏个人文件路径。可能需要官方 Microsoft Visual C++ 2015–2022 x64 Runtime；不要从第三方 DLL 网站下载文件。
- 模型缺失：重新把两个 ZIP 解压到同一父目录；完整离线包无需 Hugging Face 账号或网络。src/download_model.py 仅为显式重新下载工具，正常启动不会运行它。
- 日语识别错字：这是 Whisper small 基线，番剧多人重叠、歌曲、人名、方言或音效会影响结果；不要把模型输出当成可靠逐字证据。

## 7. 回退

停止桌面观察，取消声音勾选，再按原来方式仅看画面。
关闭 ASR 服务窗口即可；主机插件、QQ、HDS、数据库无需回退。
确认不再使用后可删除本便携文件夹，不要删除 D:\Ollama\models。
